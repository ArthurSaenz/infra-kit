## 1. RALPLAN-DR summary

### Principles
1. **infra-kit owns git; Orca owns windows.** Worktree creation, naming (`<repo>-worktrees/<branch>`), `pnpm install`, removal and branch deletion stay in infra-kit. Orca is asked to *reveal*, *lay out terminals*, and *tear down terminals of a directory that is about to be deleted* — nothing else. Never `orca worktree create` / `orca worktree rm`. `orca repo add` only after it was shown in the confirm preview.
2. **Trust the envelope, not the exit code.** Every Orca call goes through one `runOrca` that spawns with `nothrow`, parses the `--json` envelope on **every** exit code, and throws `OrcaError` on `ok: false` (the exit convention changed between 1.4.203 and 1.4.204). No bare `$\`orca …\`` anywhere else — doctor included.
3. **Hard cutover, no dual driver.** cmux code, flags, config keys and docs are removed, not aliased. One test matrix.
4. **Migration is mandatory and loud, but never bricks.** The schema stays `strict` and the file is rewritten by the existing init/setup migration pass. Until then the loader strips the three legacy keys **in memory** with one warning naming the file and `infra-kit setup` — no lazy write, no dual vocabulary.
5. **Refuse only what the operator explicitly asked for; degrade what config merely enabled; report what is found after.** A pre-mutation refusal is reserved for an *explicit* ask that cannot be honoured (`--orca` passed and Orca is unreachable) and for the one case where the mutation would destroy the caller (the caller's own Orca terminal sits inside a worktree being removed — checked at the **command preflight**, before `confirmOrExit`, never inside the per-branch loop). Config-derived `openInOrca` degrades to an `orcaSkipped` outcome with a reason; `repo add` is a preview line; a row the sidebar hides is an `orcaHidden` outcome. Deliberate asymmetry: `dev --orca` with Orca unreachable **falls back** (it mutates nothing and has a visible single-process mode), while `worktrees add --orca` **refuses** (a mutation the operator asked to be revealed) — do not "harmonise" these later.
6. **Close only what is going away.** The only `terminal close --worktree --all` callers are `worktrees remove` and `release-remove`, where the directory is deleted next. No command closes terminals it did not open in a directory that survives.

### Decision drivers
1. Orca already models what cmux groups emulated (repo → worktrees) and already discovers infra-kit's worktrees — the integration shrinks to reveal + layout + teardown.
2. Orca's CLI semantics differ in three dangerous ways (error exit code is version-dependent, the JSON envelope is the contract; `worktree rm` deletes branches; `terminal close --all` kills every session in a directory, including the caller's) — the driver must encode all three.
3. The user's layer-2 config carries `openInCmux: true`, every command parses layer 2, and the CLI auto-updates unattended — an unmigrated key must not brick the machine.

### 2.2 `infra-kit dev --orca` (replaces `--cmux`)

- `src/dev/orca-dev.ts` (from `cmux-dev.ts`): root = `findMonorepoRoot(process.cwd())` — **unchanged from cmux**, so `ik dev --orca` run from a release worktree lays its panes in that worktree's row. One terminal **tab**, title `<repo> dev`; pane 0 = `commands[0]` via `terminal create --worktree path:<root> --title … --command …`; panes 1..n via `terminal split`. `--focus` is NOT passed (cmux used `--focus false`) — Phase 0 §3.7 decides whether a background handle can be split; if not, pass `--focus` for the first create only.
- `src/dev/orca-split-plan.ts` (from `cmux-layout.ts`): pure `buildOrcaSplitPlan(commands) → { from: number, direction, command }[]` — Orca has no layout JSON, so the balanced tree becomes an ordered split list (alternating direction by depth, same tiling intent). Unit-tested.
- Shutdown: `terminal close --terminal <h0> --tab`; fallback: close each recorded handle individually. Never `--worktree --all` (principle 6: the worktree survives).
- `runOrcaDevServer` keeps the resident-supervisor + `registerSignalShutdown` shape untouched; falls back to single-process on anything but `probeOrca() === 'ready'`, when the repo is not registered in Orca, and per the §2.5 `dev --orca` visibility rule when the root row is hidden and `--focus` cannot reveal it.

### 2.5 Hidden-worktree outcome (was: refusal)

Measured: a worktree the sidebar omits still resolves for `terminal create`. So the failure mode is a *silent success on an invisible row*, not an error. After opening, `isOrcaWorktreeListed(mainRepoRoot, cwd)` decides between `orcaOpened` and `orcaHidden`. `orcaHidden` carries `{ path, fix: 'Orca → <repo> → "hidden worktrees" card → Show, or Settings → General → Workspace → external-worktree sources' }`. There is no CLI to flip visibility. Hidden-by-default is the working assumption (3/5 repo rows are `hide`), so the `repo add` preview line already says so; Phase 0 §3.1 additionally decides whether `terminal create --focus` **reveals** a hidden row — if it does, `orcaHidden` is informational; if not, the "opens when created" promise depends on one manual toggle per new repo (both existing consumer repos are already `show`).

**The gate (two independent Phase 0 answers, one code surface).** Option A is built in every cell; the answers only pick behaviours.

*Axis 1 — §3.1: does `terminal create --focus` reveal a hidden row?* Applies to `hide` repos only (runtime branch on `findOrcaRepo(main).visibility`; both consumer repos are `show`):
- **yes** → `hide` repos behave exactly like `show` repos.
- **no** → the terminals are still opened (they exist; one toggle reveals them) and the branch is reported under `orcaHidden` with the UI steps. An explicit `--orca` on a `hide` repo is honoured as `orcaHidden`, never refused (principle 5 reserves refusal for asks that cannot be honoured).

*Axis 2 — §3.7: can a background (non-`--focus`) handle be split in the same tab?* Applies to every path that must not steal focus:

| Path | §3.7 yes | §3.7 no |
| --- | --- | --- |
| `worktrees add`, single target (`--focus`) | full layout | full layout (unaffected) |
| `worktrees add --all` / multi | full layout, no focus | `--focus` + full layout on the **last** branch only; every other branch one pane, reported as `orcaOpened[].layout: 'single-pane'` |
| `reopen` | full layout, no focus | one pane per target, `layout: 'single-pane'` |
| `dev --orca` | no focus | `--focus` on the first create only |

`orcaOpened[]` entries carry `layout: 'full' | 'single-pane'`; `orcaSkipped.reason` stays the five-value enum of §2.4 (a pane that opened is never a skip).

**`dev --orca` visibility rule (§2.2)**: `dev` has no confirm, so `repo add` is forbidden there (principle 1) — `findOrcaRepo(main).registered === false` → single-process fallback with "register `<repo>` in Orca first (`ik worktrees add` offers it)". When the root worktree is not listed (`isOrcaWorktreeListed(main, root)` false): §3.1 yes → `--focus` on the first create regardless of §3.7; §3.1 no → single-process fallback with the "row hidden" line + UI steps. Dev servers never start in terminals nobody can see.

The two answers are recorded in `docs/orca-cli-findings.md` before Phase 1.

## 7. ADR

- **Decision**: replace the cmux driver with an Orca driver behind the same call sites; infra-kit remains the git owner; Orca projects replace cmux groups; reveal-on-add and additive reopen are kept, `reopen --force` is dropped, teardown is limited to directories being deleted; config keys are renamed with a mandatory setup migration plus an in-memory strip that prevents the upgrade brick.
- **Drivers**: Orca already discovers infra-kit worktrees; Orca's CLI error, `rm`, and `close --all` semantics; the user's layer-2 config carries the legacy key under an unattended auto-updater.
- **Alternatives considered**: B (dual driver), C (Orca-created worktrees), D (soft-accept both keys), E (minimal two-verb driver) — see §1.
- **Why chosen**: the smallest surface that honours both "we are leaving cmux" and "the worktree opens when we create it", with every dangerous Orca verb either forbidden or confined to a directory that is being deleted.
- **Consequences**: the "open windows" feature now requires Orca (as it required cmux); agent JSON changes (`cmux*` → `orca*`, `force` removed from `reopen`); two manual in-app steps infra-kit can only describe (CLI registration; external-worktree visibility); `stripLegacyCmuxKeys` is temporary debt.
- **Follow-ups**: remove `stripLegacyCmuxKeys` next release; ask upstream for a visibility verb if Phase 0 §3.1 shows hidden-by-default; consider `orca worktree set --comment` with the release PR URL (out of scope).
