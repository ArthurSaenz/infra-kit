## Structure

- Specs live in `src/tests/<domain>/`, one folder per business domain — never per page, browser, device, or environment (those are Playwright projects).
- A domain folder's root holds only its `*.spec.ts` files. Everything else always goes in a subfolder, even a single file: `pages/` (`.page.ts`, `.component.ts`), `fixtures/` (`.fixture.ts`), `mocks/` (`.mock.ts`), `data/` (`.data.ts`), `lib/` (domain-private helpers).
- Never nest specs in subfolders — when a domain has too many specs to scan, split it into two domains (`luggage/`, `luggage-pricing/`).
- Anything two domains share moves up to `src/pages/`, `src/fixtures/`, `src/mocks/`, or `src/lib/`; a domain never imports from a sibling domain.
- API and contract specs stay in their domain folder, told apart by suffix: `<flow>.api.spec.ts`, `<flow>.contract.spec.ts`. A suffix exists only when that suite runs in its own Playwright project.
- Visual-regression specs live in `src/visual/<domain>/<flow>.visual.spec.ts`, so baseline screenshots stay out of the domain folders.
- Auth and data preparation are `src/setup/*.setup.ts` / `*.teardown.ts`, wired as Playwright setup projects — never `globalSetup`. Saved auth state goes to the gitignored `.auth/`.

## Naming

- Every Playwright spec is `*.spec.ts`; `.test.ts` is never used in an e2e package.
- Files and folders are kebab-case.
- A spec file names a stable flow: `<feature-or-flow>.spec.ts`. No ticket ids, sequence numbers, or `common` / `main` / `smoke`.
- Non-spec files never carry `.spec` / `.test`. A spec never imports another spec.
- `describe` is a short domain context in Title Case (`Checkout`).
- `test` is a lowercase behaviour phrase — action or condition plus the observable outcome (`rejects an expired coupon without changing the total`). No `should`, `test …`, `works`, or case numbers.
- `test.step` is a verb plus a business operation (`Pay with the saved card`), 3–6 per long flow — never one step per click or fill.
- Screenshot baselines are named by UI state (`checkout-payment-error.png`), never `screenshot-1.png`.

## Tags

Run categories are tags (`{ tag: [...] }`), never file names. Only these four exist:

- `@smoke` — the fast post-deploy check; every domain has at least one.
- `@readonly` — creates and changes nothing, so it is safe against any shared environment.
- `@mocked` — every backend call is mocked; runs without a live API.
- `@slow` — excluded from local runs with `--grep-invert @slow`.

Never tag a browser, device, or environment, and never add `@flaky`; fix the test or skip it with a linked issue.

Lint enforces the mechanical part: `@wl/e2e-file-layout` the Structure folders and the `.spec.ts` suffix, `@wl/e2e-file-order` imports first and then the class, the `extend` call, the `test.*` calls, the mock function or a `lib/` file's exports — constants and helpers below, `@wl/e2e-page-object-member-order` fields → constructor → getters → public → private methods, `@wl/e2e-top-level-describe` one top-level describe holding the setup, hooks and tests, `@wl/e2e-describe-order` setup → hooks → tests inside it, `@wl/e2e-test-tags` the tag list, `@wl/e2e-test-title` the missing `should`. The rest of Naming — `describe` in Title Case, no ticket ids, outcome-bearing titles, `test.step` wording — is on the author and the reviewer.
