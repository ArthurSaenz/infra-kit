## Learnings

- The zx mock in gh-release-prs.test.ts had a fallthrough returning the `gh pr list` JSON, so
  `git status --porcelain` answered "[]" = dirty. Any new git READ inside a mocked-zx module
  silently inverts. New mocks answer per command and support `$({quiet:true})`.
- PM4 (commit-msg hook rejecting the empty commit) was mis-scoped as a landing gate: the empty
  commit ALREADY runs today, so a hook would break the command as it stands. A0 only moves the
  failure ahead of the push, which is strictly better. Gate dropped.
- git-guard.test.ts mocks src/lib/git-utils wholesale, so ANY new import there breaks it with
  "No X export is defined on the mock" — add to the factory, not just to the source.

## 2026-09-10 — `infra-kit setup` output defects (ralph, session 9526c284)

Trigger: a screenshot of a real `infra-kit setup` run showing three separate problems.

### What was actually wrong

1. **`aws update` is not a command.** `dependency-registry.ts` mapped a script-installed aws to
   `managed(['aws','update'])` with a comment calling it "the vendor's own updater". AWS CLI v2 has no
   `update` subcommand — argparse answers `argument command: Found invalid choice 'update'` and exits
   252. The recipe passed every risk conjunct (no sudo, no network script, manager owned + present), so
   it RAN, and `setup` reported `failed  aws` on every machine with a script/pkg-installed aws. Nothing
   pinned the recipe in a test, which is why it survived.
   Fix: `updateFor` now takes `(manager, binRealPath)` and a script install re-runs the vendor
   installer (`https://awscli.amazonaws.com/v2/install.sh`), which self-detects an existing install and
   passes `--update` internally. Layout-aware: `/usr/local/aws-cli/` -> `sudo … | bash -s -- --system`;
   otherwise the user-scope form. Both fetch a network script, so both are REFUSED and printed.

2. **zx relays child stderr.** zx 8.8.5 pipes child stdout but forwards child STDERR to the parent's.
   `default-probe-deps.ts` used a bare `$`, so a read-only probe of an absent binary printed
   `/bin/bash: portless: command not found` into the terminal of every `setup` AND `doctor` run.
   Fix: `$({ quiet: true })`, built lazily inside the function — at module scope it fires on IMPORT,
   which crashes any test that mocks `zx` with a tag-only fake before its fixtures exist.

3. **`stdio: 'inherit'` in the installer.** brew/npm chatter interleaved with the summary the command
   exists to print. Fix: capture, narrate each step in infra-kit's own voice first, and put the tail of
   the child's own stderr into the failure detail — which is where the `exited 252` diagnosis went.

Plus: `formatRecipe` used `steps.join(' ')`, so a refused `bash -c 'curl … | bash'` printed as a line
that does NOT reproduce the recipe. Extracted `shellQuote`/`shellLine` from `portless-driver` into
`src/lib/shell-quote/` and used it in both.

### Learnings worth carrying

- zx's `$` is BOTH a tag and a factory. A `vi.mock('zx')` that models only the tag call crashes the
  moment production code writes `$({ … })`. Two doctor mocks needed teaching; `src/lib/vendor/__tests__/zx-mock.ts`
  already had the both-shapes pattern and is the one to copy.
- Never create a configured zx shell at module scope in a module that tests import transitively.
- The CLI's local eslint enforces `max-jsdoc-lines` (<=15 prose lines) — rationale goes in `//` notes
  below the block, not inside it.
- Running `infra-kit setup` to verify regenerates every CLAUDE.md guidance block with the current
  version stamp. Revert those before committing; they are not part of the change.
- `pnpm run qa` is RED on HEAD for unrelated version drift: `publish-lifecycle.test.ts` and
  `lockstep.test.ts` assert infra-kit@0.5.1 against @slip-stream-kit/*@0.5.0 and config@0.4.0. Check
  whether a red is one of those two before blaming your diff.

### Review round 1 — rejected, three blockers (all now fixed)

1. **`spawnSync` had no `maxBuffer`.** Node's default is 1 MiB and at the limit it does not truncate —
   it SIGTERMs the child and returns `ENOBUFS`. A `brew install` building from source clears 1 MiB
   routinely, so capturing output introduced a way to kill an install that `stdio: 'inherit'` could
   never have. Worse, `describeFailure` tested `result.error` first, so the kill reported as
   "could not start" — the one description guaranteed to be false. Now 64 MiB with an explicit
   ENOBUFS branch ahead of the generic one.
2. **The leak was only half-fixed.** `doctor.ts`'s `checkCommand` and `probeIde` still used a bare `$`
   over possibly-absent binaries, across ten call sites. Extracted `lib/quiet-shell` and used it in
   both places plus the probe.
3. **`startsWith` for the aws `--system` layout.** This repo already ships `isWithin`, whose docblock
   argues against exactly that, and the memory note "realpath asymmetry breaks path containment"
   records the failure mode. Verified: `isWithin` rejects the `/usr/local/aws-cli-backup` sibling that
   `startsWith` accepts, and `safeRealpath` handles a parent that does not exist.

Also taken from the review: `updateFor(manager, binRealPath)` was one parameter too many — the manager
is `identify(binRealPath)`, computed by the same spec, so the pair could disagree in ways the probe can
never produce. Collapsed to `updateFor(binRealPath)` via `updateWhenIdentified`. Test sweeps now range
over layouts rather than over `DependencyManager` strings, several of which no `identify` can return.

Fallout worth remembering: teaching zx's factory form to the doctor mocks broke FOUR suites, and the
shared helper had to be imported INSIDE the hoisted `vi.mock` factory (`await import`) because
`doctor.ts` pulls `zx` in at module scope, leaving a top-level binding in its TDZ. A test that stubs
`vi.mocked($).mockResolvedValue` also clobbers the factory shape, not just the tag.
